# Public image delivery

API clients can send `x-viptv-image-delivery: direct` for native/desktop images, or `proxy` when a browser fetcher needs CORS. Opted-in JSON responses translate only recognized Simkl asset fields; unrelated assets, verified MetaHub logos, descriptions and credentials remain unchanged. Missing/unknown negotiation preserves legacy responses. Wire models and native bindings remain unchanged.

Direct references point to the official Simkl CDN. Proxy references are relative `/api/images/simkl/{folder}/{hash}_{size}.{extension}` and must resolve against the client's active API origin, including approved native/LAN aliases. No canonical origin or authentication token is embedded in an image URL. Recognized resolved proxy paths in saved cards can also be translated without fetching their original host.

The unauthenticated GET/HEAD image route accepts only the known `posters`, `fanart` and `episodes` descriptors, supported sizes/extensions, and bounded alphanumeric path segments. It cannot accept arbitrary URLs, hosts, query credentials or traversal. Size suffixes are the ones Simkl serves: posters `_s`, `_cm`, `_c`, `_ca`, `_m`, `_w`; episodes `_m`, `_c`, `_w`; fanart `_w`, `_medium`, `_mobile`, `_s48` and `_d`, where `_d` alone is JPEG-only. Fanart's legacy `_w` alias maps to the documented `_medium` size for opted-in delivery. Images are fetched through pinned public DNS, HTTPS, no redirects, no ambient proxies, and no forwarded cookies/authorization. Upstream bodies have a 3-second deadline and 2 MiB limit; six requests may fetch concurrently. Permit waiting and duplicate-request coalescing apply backpressure within one eight-second total request deadline. Local queue/coalescing timeouts return retryable 503 and are never negative-cached; only an attempted upstream failure enters the ten-second negative cache. A coalesced cache is bounded to 128 entries/32 MiB, with five-minute positive and ten-second negative entries. The strict byte budget remains enforced when entries are active.

Returned bytes must have JPEG, PNG, WebP or GIF signatures. Animated GIF artwork keeps its frames; the proxy passes the bytes through and never re-encodes them. Simkl publishes its own artwork as `.webp` apart from fanart `_d` and avatars, which are `.jpg`; the GIF signature covers artwork paths a saved card or add-on may still carry, and the served type comes from the bytes rather than the descriptor. The endpoint sets the derived image Content-Type, `nosniff`, `Access-Control-Allow-Origin: *`, and a policy that matches how the bytes are addressed: descriptor URLs are stable, so they carry `public, max-age=300` plus a content `ETag`, and `If-None-Match` returns 304 without a body. A replaced upstream image therefore appears within five minutes, and the advertised freshness never outlives the server copy. Public image OPTIONS supports ordinary image headers and the negotiation header; it does not widen authenticated API origin/credential policy. Authentication headers and cookies are unnecessary for public images.

Provider reference: [official image conventions](https://api.simkl.org/conventions/images).

Regression coverage holds every fetch permit for longer than the one-second queue limit, then verifies successful image delivery; it also exhausts the total queue deadline and immediately retries the same descriptor successfully without waiting for negative-cache expiry. No arbitrary proxy URL, new image host, redirect relaxation or TLS exception is introduced.

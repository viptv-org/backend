# Public image delivery

API clients can send `x-viptv-image-delivery: direct` for native/desktop images, or `proxy` when a browser fetcher needs CORS. Opted-in JSON responses translate only recognized Simkl asset fields; unrelated assets, verified MetaHub logos, descriptions and credentials remain unchanged. Missing/unknown negotiation preserves legacy responses. Wire models and native bindings remain unchanged.

Direct references point to the official Simkl CDN. Proxy references are relative `/api/v3/images/simkl/{folder}/{hash}_{size}.{extension}` and must resolve against the client's active API origin, including approved native/LAN aliases. No canonical origin or authentication token is embedded in an image URL. Recognized resolved proxy paths in saved cards can also be translated without fetching their original host.

The unauthenticated GET/HEAD image route accepts only the known `posters`, `fanart` and `episodes` descriptors, supported sizes/extensions, and bounded alphanumeric path segments. It cannot accept arbitrary URLs, hosts, query credentials or traversal. Size suffixes are the ones Simkl serves: posters `_s`, `_cm`, `_c`, `_ca`, `_m`, `_w`; episodes `_m`, `_c`, `_w`; fanart `_w`, `_medium`, `_mobile`, `_s48` and `_d`, where `_d` alone is JPEG-only. Fanart's legacy `_w` alias maps to the documented `_medium` size for opted-in delivery. Images are fetched through pinned public DNS, HTTPS, no redirects, no ambient proxies, and no forwarded cookies/authorization. Upstream bodies have a 3-second deadline and 2 MiB limit; six requests may fetch concurrently. Permit waiting and duplicate-request coalescing apply backpressure within one eight-second total request deadline. Local queue/coalescing timeouts return retryable 503 and are never negative-cached; only an attempted upstream failure enters the ten-second negative cache. A coalesced cache is bounded to 128 entries/32 MiB, with one-hour positive and ten-second negative entries. The strict byte budget remains enforced when entries are active.

Returned bytes must have JPEG, PNG, WebP or GIF signatures. Animated GIF artwork keeps its frames; the proxy passes the bytes through and never re-encodes them. Simkl publishes its own artwork as `.webp` apart from fanart `_d` and avatars, which are `.jpg`; the GIF signature covers artwork paths a saved card or add-on may still carry, and the served type comes from the bytes rather than the descriptor. The endpoint sets the derived image Content-Type, `nosniff`, public one-day immutable caching and `Access-Control-Allow-Origin: *`. Public image OPTIONS supports ordinary image headers and the negotiation header; it does not widen authenticated API origin/credential policy. Authentication headers and cookies are unnecessary for public images.

Qualification found the real Season 2 episode paths valid as `_w.webp`; direct targets omitted CORS headers. The external wsrv proxy showed client/WAF variability and a 3–4-second native cold fetch. Actual negotiated direct and owned proxy images returned 200 WebP, with warm owned-proxy reads around 5 ms. Performance still depends on the public CDN and connection warm-up; private aggregate measurements remain in local proof files rather than git.

Provider reference: [official image conventions](https://api.simkl.org/conventions/images).

Regression coverage holds every fetch permit for longer than the previous one-second queue limit, then verifies successful image delivery; it also exhausts the total queue deadline and immediately retries the same descriptor successfully without waiting for negative-cache expiry. A 72-image public catalog burst reproduced four 502 responses under the old queue behavior. No arbitrary proxy URL, new image host, redirect relaxation or TLS exception is introduced.

After the backpressure fix and a cold owned API restart, the same 72-descriptor burst returned 72/72 HTTP200 bodies with valid image signatures (maximum 2,246 ms). Canonical and LAN trusted-HTTPS reads returned actual WebP bytes with `Access-Control-Allow-Origin: *` and `nosniff`; warm reads measured 9 ms and 4 ms. These are host delivery measurements; browser traversal/rendering is independently checked by the consuming client. The full runtime-feature server suite passed 406 tests with 10 intentionally ignored.

A subsequent browser cold-start investigation observed 37 image502 responses in an earlier Home→Details run. Later fresh Chromium Home-row→Details traversal immediately after an owned API restart returned all 53 public descriptor requests200, with one bootstrap, one metadata request and no JavaScript errors. URL-free upstream failure-class/folder/timing diagnostics were added; that successful traversal emitted no failure records. The earlier37 responses' upstream cause remains unconfirmed and is not claimed fixed by those diagnostics. No deadline, destination allowlist, TLS or proxy exception was changed in this follow-up.

# Origin-aware server personal library

The v3 library and progress endpoints keep add-on lookup provenance separate from shared storage identity. This is an additive server persistence schema; the old `favorites`, `progress`, `queue_hidden`, and continuation cache remain the legacy interface and are not relabeled with a current connector incarnation.

## Authority and retention

A new origin-bearing save/progress write obtains `origins::persistence_card` before acquiring the database lock. Host-verified metadata can provide an unambiguous shared external alias. A posted external ID only constrains the lookup and cannot supply alias authority. Intrinsically canonical raw IMDb IDs with strict typed coordinate spelling remain shared, as in the qualified native contract; raw Simkl IDs are shared only under the Simkl origin. This storage convention grants no metadata, source, playback, or parental-policy authority. The transaction revalidates the request lease, selected profile, current origin/incarnation, current integration assignment, parental policy, and captured metadata proof. Metadata proof fences the issuing source configuration and profile configuration between the network read and commit.

New records retain the original raw lookup ID, complete assertions, and stable connector incarnation. Verified lookup bindings are additive: a connector changing opaque `foo` from canonical title A to B retains A's earlier binding/state. Another connector identifying A can share its verified record without making its raw lookup ID the metadata request for the first connector. If later metadata loses its shared alias, the new private record does not inherit A's saved date or watch count; A remains separately retained. Contradictory assertions for the same private storage key are rejected. An unverified write does not replace existing contradictory expected assertions.

Host-verified canonical Simkl import provenance remains a shared membership alias; its proof is the server-owned import record, not the spelling of an old raw ID. Alias tokens do not count as additional logical favorites. Old ambiguous records remain `legacy_identities` in complete membership snapshots. Canonical public legacy IMDb identities remain in `identities`. Origin-bearing records and retained bindings appear in `scoped_identities`, including complete external-ID, episode, and edition assertions. Membership is bounded to 10,000 logical favorites, 100,000 retained lookup bindings and 16 MiB; failure rolls back a mutation instead of acknowledging an incomplete snapshot. Playback is bounded to 50,000 scoped records. Progress heartbeat updates use indexed lookup/primary-key reads, not full-history hydration.

## HTTP contracts

Existing methods and routes remain:

- `PUT /api/v3/profiles/:profile/library` with `{ "card": Card }`.
- `PUT /api/v3/profiles/:profile/progress` with `{ "record": PlaybackRecord, "ended": false }`.
- `GET /api/v3/profiles/:profile/library/membership` returns complete shared, scoped and legacy membership plus revision.
- `DELETE /api/v3/profiles/:profile/library/:kind/:id?metadata_origin=<JSON>&card=<JSON>` selects an exact stored origin-bearing favorite. Both values are URL-encoded and must agree with the path and each other. A stale or removed installation can select its own stored record. It cannot delete the reinstalled connector's unrelated private record or fall back to ambiguous/private legacy rows. An origin-only or mismatched selector is rejected. A DELETE with neither selector retains the old legacy-only behavior.
- `PUT /api/v3/profiles/:profile/continue/visibility` accepts optional `metadata_origin` and `card` alongside the existing `identity`, `parent_identity`, and `hidden`. Both new selectors are required together. Only saved history or a current bounded prepared-next result can identify the scoped queue group. Legacy raw `queue_hidden` rows never hide origin-bearing records. This additive server capability currently has no KMP UI caller.

A scoped removal does not remove a separate ambiguous/private legacy favorite with the same raw ID. An exact trusted shared storage key does remove its canonical legacy backing row together, matching the qualified Store contract and the single logical saved-state toggle. Intrinsic public canonical selectors can remove their canonical legacy-only row. Known Simkl import aliases use the existing authoritative import receipt, never posted external-ID hints; origin-bearing save, resume, statistics and removal preserve that canonical mapping. Ambiguous legacy records stay explicitly visible as legacy membership.

The v3 library, statistics, history, Home/Continue and complete membership read the scoped records. Home uses the typed merged Continue projection and an indexed first-page favorite projection (24-row batches until 12 policy-visible cards), rather than hydrating all 10,000 favorite cards/statistics. HTTP regressions check actual bootstrap Home rows as well as the separate library and Continue routes. History and Continue combine and paginate legacy and scoped observations; private collisions are not deduplicated by raw ID. Clearing selected-profile local history clears both progress stores and both next caches, preserving favorites and not invoking a remote provider deletion.

## Viewing semantics

Server time supplies progress activity/completion timestamps; posted timestamps and watch counts are ignored. Completion transitions increment only counts observed by this server, and repeated completion callbacks do not increment again. Previously unknown canonical legacy watch totals remain unknown. Legacy unknown added dates remain unknown when a corresponding verified scoped favorite is written. Known-duration ended callbacks use the actual duration, matching the old typed progress behavior.

Prepared next results are isolated by profile, origin/incarnation, raw identity and full expected assertions, profile configuration and issuing source configuration. They expire after five minutes and are capped at 200 per profile. Prepared-next results do not create invented history rows. Private history never uses the raw-ID legacy next cache. Gateway resume likewise selects an exact origin/assertion record or a host-verified shared storage key; opaque private lookups never fall back to raw-ID legacy progress, and completed records do not resume.

## Verification

The focused regressions live in `server/src/engine_v3/scoped_library_tests.rs`. Their local HTTP metadata fixtures deliberately return colliding opaque IDs and controlled canonical aliases. They exercise favorites/progress/membership/statistics/history/Continue, exact removal after alias remap and reinstall, unverified constraints, profile isolation, metadata proof fencing, unknown legacy values, loss of alias proof, canonical continuation deduplication and scoped queue visibility. These are server/fixture tests, not a real decoder or physical-TV qualification. The final merged normal gate passed **503 tests** (487 library + 16 CLI; eight existing ignored), with a 19.71 s library runtime. The SDK-feature gate passed **505 tests** (489 library + 16 CLI; nine existing ignored), with a 19.79 s library runtime. These include the final IDs-only membership, shared-key statistic merge, Home, canonical unsave and exact caption-context regressions. Receipts: [qualified normal](evidence/scoped-library-2026-10-15/qualified-normal.log), [qualified SDK](evidence/scoped-library-2026-10-15/qualified-sdk.log). Runtime-candidate qualification remains separate.

Gateway resume now uses the verified source grant's exact scoped Card, with primary-key/authoritative binding lookup and canonical-only legacy fallback. A private origin never resumes another origin's same raw ID or an ambiguous legacy row. Metadata proof also captures delegated metadata connectors, so a search-only issuer cannot retain alias authority after its actual metadata connector's credentials/manifest change. Source discovery rebuilds title/external-ID/episode matching fields from the verified host Card instead of forwarding posted scalar hints; this prevents an approved title's proof from authorizing a different IPTV match.

The final gates above qualify the IDs-only membership and shared-key statistic follow-ups. Membership now reads bounded identity/origin/parent columns rather than deserializing full presentation cards, with regressions for missing presentation fields and current per-origin parental filtering. Shared-key statistics retain authoritative import rating/totals/provenance while preserving current local watch observations, lookup provenance and unknown lifetime counts; ambiguous legacy and unverified private aliases cannot select those imports.

# Typed parent title selection

Parent administration uses the actual browser household-manager session and its existing parent grant. A restricted selected profile requires a live grant even when the target is another owned child. The target does not become the selected media profile, and normal media/library routes remain selected-profile only. Target ownership, target policy/configuration revisions, actual session/policy and parent-grant authority are checked before and after provider work and inside mutations.

`GET /api/v3/parent/search?query=...&profile_id=<optional owned target>` uses that target's assigned integrations. Omitted `profile_id` selects the actual current profile. Normal `/api/v3/search` rejects a target-profile parameter. Search returns `{rows:[...],complete:Boolean}`. Each row has `id`, `title`, `provider_id`, nullable `addon_id`, `state`, safe nullable `message`, and `items:[{card:Card,approval_supported:Boolean,message:String?}]`. Parent previews hide observed adult classifications and permit reviewing unrated titles; they never grant playback authority. Missing metadata capability is reported truthfully.

`POST /api/v3/profiles/:target/approvals` accepts existing fields `{type,id,approved,metadata_provider_id?,metadata_addon_id?}` and new optional `metadata_origin:MetadataOrigin` plus `card:Card`. New private approvals require the full expected Card and stable origin from a host-issued search/detail result. The host refetches authoritative metadata, checks expected valid external-ID/episode/edition assertions, observes the real parent and episode edges, and rejects adult titles. A stale `foo→IMDb A` selection cannot approve a newly observed `foo→B`. Client ratings, aliases and episode lists never establish authority.

`MetadataOrigin` is `{provider_id:"stremio",connection_id:"addon:<id>",incarnation:"<32 lowercase hex>"}` or `{provider_id:"simkl"}`. The incarnation survives credential/manifest/enablement edits but changes after connector deletion/reinstallation, even when its numeric ID is reused. Mutable source/profile revisions remain separate access fences. A Stremio origin cannot claim the reserved Simkl namespace.

Canonical IMDb and Simkl approvals retain their shared legacy-compatible policy rules. Private observations, assertion-bearing lookup bindings and grants use additive scoped tables. Old ambiguous opaque approvals remain explicitly legacy and cannot authorize a new explicit origin's same ID. Verified complete metadata can establish a shared canonical identity; catalog external-ID hints cannot. Age conflicts remain conservative, all adult observations reject access, and ambiguous episode-parent edges fail closed. A profile's blocked list outranks an approval for the same title, and unrated or conflicting ratings are served only to a profile that allows them ([parental controls](PARENTAL_CONTROLS_V3.md)).

`GET /api/v3/profiles/:target/approvals?offset=0` returns `{items:[{id,type,name,poster,metadata_provider_id,metadata_addon_id,approval_supported,metadata_origin?,card?}]}`. Scoped entries include the authoritative saved Card. Reload this list after mutation before enabling exact revoke: the search preview may not contain the fresh stored alias assertions. Revoke uses `approved:false` with that saved Card/origin and remains possible after its connector is disabled/deleted. Legacy entries keep their original scalar revoke contract; the host does not guess a modern origin for them.

Modern detail/subtitle query parameters carry URL-encoded JSON `metadata_origin` and `card`; source/next requests carry the same objects in JSON bodies. These consumers check the exact scoped lookup and current policy. Source jobs, registered stream grants, gateway playback proof and subtitle selections retain captured metadata configuration and title authority. Revocation and connector/profile changes invalidate future admission, polls, heartbeat and caption loads without deleting saved history.

No account-edit, email, parent-PIN recovery or provider policy change is implied by these routes. No migration is deployed by this work.

## Refresh maintenance boundary

A bounded Simkl token rotation checks the complete caller session, parent grant, profile policy, assignment and link immediately before dispatch. After the provider consumes the one-use refresh token, sealing its replacement is credential maintenance for the persistent account/profile link. Policy/configuration changes or one browser's logout still prevent content delivery, but do not discard the replacement for an unchanged owned link. Persistence compares the exact original encrypted credential and link revision in the final write. Unlink, profile/account deletion, ownership transfer or a replacement/relinked credential prevent that write; a response never resurrects the old link. The maintenance path grants no browsing, playback or parent authority.

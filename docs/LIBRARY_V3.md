# Scoped library pages

`GET /api/profiles/:id/library` and native `LocalEngine.libraryPage(profile, queryJson)` return `LibrarySnapshot`: cards, cursor, effective query, embedded `QueryControl` choices, list availability, and actual statistics keyed by canonical media identity. Existing `cards`, `next_cursor` and `complete` consumers remain compatible. One page request applies filters and retrieves current choices.

There is one main Library (`source=favorites`, the default), containing saved and imported titles. `source=simkl` remains a compatibility request alias; it does not create a separate collection or selector. Import requires this profile's linked credential and enabled Authorization assignment, and never changes the selected metadata provider. Existing imported data remains local after unlink. The compatibility alias retains typed authorization/configuration availability; normal Library remains usable without Simkl.

Common queries are `sort=last_watched|name_asc|name_desc|times_watched|date_added`, `show=all|watched|not_watched`, `type=all|movie|series|anime`, `genre`, and `added=this_year|this_month|last_7_days`. Imported provider facts additionally support `status=watching|plantowatch|hold|completed|dropped`, `rated=rated_8_plus|not_rated`, `episodes_left_max=9`, and `show=has_new_episode|not_started|caught_up|episodes_to_air`. Empty optional string choices mean Any; omit empty numeric choices. Offset is bounded at 10,000 and page limit at 100.

Statistics keep unknown historical dates/counts null. Personal `user_rating` comes from the linked watchlist and is independent of catalog ratings. Aired counts use provider total minus not-aired counts. The provider next-unwatched marker determines caught-up status even when the user skipped old episodes. Individual episode completions do not fabricate whole-series rewatch totals. Native and favorites counts record only observed completion transitions, without rewriting legacy history.

The read-only Simkl adapter coalesces private reads per session family, profile, configuration and link revision. It caches for 60 seconds, then checks `/sync/activities`. Changed watchlist buckets merge `date_from` deltas; rating-only changes read `/sync/ratings`; removals reconcile canonical IDs. Null or omitted empty buckets are accepted. Memos are removed before caching. Each private read is bounded by 12 seconds and 4 MiB; no external list/history/status writes or expanded OAuth scopes occur.

Simkl all-items does not supply genres, including `extended=full`. Genre hydration runs in the host, using canonical detail reads and the existing coalesced metadata cache. There are at most three worker requests globally, a 3-second per-title deadline, 90-second sweep deadline and 2,000-title limit per sweep. Requests and publication validate profile/configuration/link authority. The initial list does not wait for hydration. Subsequent Apply reads reuse verified cards and expose actual genre choices. Warm public detail cache entries also seed a new private projection without egress. `refresh_after_millis` is nullable (default null) and requests a 4-second aggregate page refresh only while import or bounded genre enrichment is active; it becomes null on completion/deadline, so clients need not parse human-readable reasons or issue per-card requests. While titles remain unknown, `reason` states the verified/total count; a genre-filtered page returns verified matches with `TemporarilyUnavailable`, never silently treating unknown titles as definitive nonmatches. A later Apply retries missing titles after a 10-second cooldown measured from worker completion. Libraries larger than one sweep remain explicitly partial until further bounded sweeps finish.

The owned local QA server continues until explicit process termination. It does not have a 24-hour or shorter automatic expiry; session expiry remains normal authentication behavior.

Official provider references: [all-items](https://api.simkl.org/api-reference/simkl/get-all-items), [sync guide](https://api.simkl.org/guides/sync).

## Import and startup receipts

Bootstrap includes `library_membership: LibraryMembershipSnapshot` with `{identities: MediaIdentity[], revision, complete:true}`. This uses bounded favorites/mapping SQL only, without card projection or provider reads. GET `/api/profiles/:id/library/membership` returns the same object. At most 10,000 saved rows and 10,000 verified aliases are accepted; exceeding a bound returns an error rather than a falsely complete set. Provider-qualified aliases only come from persisted verified imports; removing an imported alias resolves to its saved canonical row. Use this receipt for toggle state instead of fetching every Library page at startup. Home remains bounded to 12 saved titles; Library pagination serves the actual open Library screen.

Successful `PUT /api/profiles/:id/library` and `DELETE /api/profiles/:id/library/:kind/:id` return `{ok:true,saved:true|false,library_membership:LibraryMembershipSnapshot}`. Replace toggle membership from this complete lightweight receipt; do not hydrate card pages or make another aggregate request after a mutation. Verified imported aliases resolve to the saved canonical row, and removal excludes both canonical and alias identities. Mutation and receipt projection share one database transaction and the existing ownership/profile/kids filters. The projector reads the held connection without taking the database lock again; a bounded-snapshot failure rolls the mutation back rather than acknowledging partial membership.

Bootstrap also includes nullable `library_import: LibraryImportStatus`. GET or POST `/api/profiles/:id/imports/simkl` starts/coalesces the same profile-scoped task and returns `{provider_id,running,checked_at_millis,library_revision,added_titles,imported_history,preserved_local,unresolved,availability,refresh_after_millis}`. Home and Library schedule it in the background; they do not wait for a private remote list read. Private snapshots and activity watermarks persist with account/profile/configuration/link fencing, so restart rechecks activities rather than requiring another full pull. Import tasks have a 90-second overall deadline, at most three concurrent paused-title metadata reads and at most 100 active paused-title resolutions per run. Unresolved counts are explicit; tasks stop and refresh hints become null on completion/deadline. Authorization scopes are unchanged.

Clients may refresh the aggregate Library page at its nullable hint while the route is open. For Home, refresh once when import becomes terminal and its `library_revision` exceeds the current Home revision; refresh membership at the same transition. Stop import-status polling when `running=false`. A foreground application may schedule a later read after the host's 60-second private-cache interval; this is not a background all-items timer. No per-title client metadata requests are needed.

Saved titles stored without a card (Stremio imports keep only a name and poster) gain the card Details shows in a bounded background run per profile that only applying a Stremio import starts. GET `/api/profiles/:id/library/details` reports that run as `{running, done, filled, total}`: whether it is active, titles looked up so far, those that actually gained a card (a profile without a metadata add-on that knows a title looks it up without filling it) and titles it has found to fill. `total` is 0 until the run has listed the profile's rows and can grow when a backlog or a newer import extends the run; `done` never decreases within a run. Finished counts stay until the next run starts. The answer is in-memory counters for the session's own selected profile only (other profiles are refused); it carries no titles, IDs or URLs, does no database scan and never starts a run. Clients poll it at a modest interval while showing import progress and stop at `running=false`; the library revision advances as rows fill, so Home and My List pick the cards up through the ordinary revision check.

All-items uses `extended=full&include_all_episodes=original&episode_watched_at=yes&episode_runtime=yes&episode_tvdb_id=yes`. It never requests synthesized watched rows or PRO rewatches. Only original per-episode dates become historical events; an aggregate completed count does not create missing episode events or dates. Anime history retains provider absolute order without inventing aired seasons. Paused percentage becomes estimated position only with verified title/runtime and exact episode mapping; unknown mappings/runtime remain unresolved. Paused title lookup uses the explicit playback category plus the canonical title ID, including validated `simkl`/`simkl_id` aliases; a numeric match in another category cannot choose its metadata/runtime. Multiple conflicting title wrappers remain unresolved. The first 100 pause resolutions are bounded; larger sets remain explicitly unresolved for this checkpoint.

Imported membership/statistics carry `LibraryStatistics.provenance` (provider, original identity, first-import time, source activity and link revision). Local membership removal tombstones survive future imports. Original added dates remain unknown when absent; first-add dates are preserved. Existing local progress is never overwritten. An unchanged importer-owned receipt may advance only with a strictly newer provider event, and newer title activity wins. History deletion/clear is preserved by tombstones/cutoff. Read/import writes go directly to the local database, never through outbound scrobble/history scheduling; importing does not export anything to Simkl. Local and imported lifetime counts remain unknown unless the provider supplies a real count.

Imported original completions do not appear as resumable Continue cards by themselves. The importer prepares at most 100 currently-watching next-item transitions with three concurrent host reads, inside the same bounded task. A transition requires the provider's actual `next_to_watch_info`, an aired matching episode document and an unchanged importer-owned latest history anchor. Anime absolute numbering must map through the provider's explicit TVDB episode coordinates. Missing/ambiguous mappings remain unresolved and do not produce invented season/episode IDs. Paused and Next anime resolution share the complete scoped episode document: absolute AniDB number, Simkl episode ID and explicit TVDB hints must agree on one regular episode. Absolute-only pauses can resolve through that document to different aired season/episode coordinates. Duplicate regular absolute numbers, duplicate episode IDs or a TVDB coordinate assigned to different regular episodes remain unresolved; projecting only the requested row cannot conceal a conflict elsewhere in the document. Preparation only updates the existing continuation cache; no zero-position history event is inserted. Paused records and newer local playback/corrections take precedence. The resulting Home card targets the verified next episode with no resume progress bar.

When a verified Simkl title maps to an existing canonical IMDb saved row, generic detail lookup and Home enrichment reuse that persisted mapping while retaining the saved title and episode identities. Current provider metadata must reconfirm the IMDb equivalence; ambiguous or changed mappings fail closed. Clients continue using the same generic detail route, without translating provider IDs.

## Experimental qualification

Owned read-only provider import qualification added 154 saved titles and 2,896 original/paused history records. All previously existing progress/favorite rows were byte-for-byte preserved, and tracking receipts did not change. Initial Library returned in 12 ms with a 4-second refresh hint; complete membership held 159 identities without card-page hydration. A subsequent verified-next sweep prepared 87 transitions and returned 12 Home Continue cards (8 prepared next episodes) in 307 ms. The host reported 11 unresolved entries explicitly. All 2,898 resulting history rows and 159 saved rows remained unchanged during that sweep; preparation wrote only continuation cache state. These are aggregate metrics; private account documents/proofs are not committed.

The regression suite covers newer local progress, manual receipt changes, link revisions, durable removals/clear cutoffs, first-added dates, canonical aliases and alias removal, stable revisions, original episode dates, no synthesized history, exact paused episode mapping, and regular-anime selection when specials reuse an absolute number. No production deployment or external list/history write is part of this checkpoint.


## Anime identity regression checkpoint

Isolated fixtures reproduced (1) a show pause selecting movie metadata from an equal numeric-ID entry in a different canonical category, (2) a valid absolute-only anime pause being dropped despite an explicit unique aired mapping, and (3) a prepared Next target overlooking another absolute episode with the same aired mapping. These are synthetic conflict/acceptance fixtures, not evidence that real Simkl title IDs collide. A source absolute52→airedS2E1 fixture now imports exactly the provider-asserted episode; contradictory hints and ambiguous mappings stay unresolved. Existing unrelated/newer local progress, other-profile progress and original completion history are preserved. Import tests observe zero outbound history/scrobble writes and zero tracking receipts.

This checkpoint does not establish real-account anime import, anime source playback, mapping coverage for unmapped titles or whole-catalog acceptance. The existing100-title/90-second bounds still apply. Prepared QA executables remain a separately pinned checkpoint until coordinated activation.

# Canonical episode windows

`GET /api/v3/meta/:kind/:id?offset=0&limit=96` returns a bounded window of exact episode cards and the next global cursor. Optional `limit` is 1–128; omitting it preserves the 24-card default. The selected-profile Simkl detail route accepts the same limit. Invalid limits are rejected before provider traffic. `offset` is forwarded through the generic selected-provider adapter; it does not require a provider-specific client endpoint.

`DetailSnapshot.seasons` is additive, defaulting to an empty list for old responses. Each entry contains `season` (nullable), `episode_count`, and `offset`. Offsets refer to the same canonical sequence used by episode windows. Explicit seasons are ordered numerically, including Season 0; unknown-season episodes form a final null group. Identifiers and parent identity remain unchanged. The index comes from the already-fetched provider episode document, so it requires no extra source/provider reads. Server policy filtering occurs before index construction and paging.

A client can select a season by requesting its offset, retain and deduplicate previously fetched cards, then request `season.offset + loaded_count` until the selected season's known count is loaded. A bounded window may include the beginning of the next season; those cards remain valid and can be retained. The next global cursor alone does not imply that the selected season has more episodes.

Native `cachedDetail` can derive an unvisited window from the scoped body already supplied to `projectDetail`. It retains at most four series documents (8 MiB), expires them after five minutes, validates configuration scope, and registers returned exact episode cards for subsequent source admission. This avoids re-downloading the full addon metadata document for each season/page. Additive native `detailPage(profile, kind, id, offset, limit): String?` reuses cached snapshots/documents with the requested limit; null means the host needs its existing planned HTTP fetch. `projectDetailPage(operation, body, offset, limit): String` projects that response. Existing `cachedDetail` and `projectDetail` remain 24-card wrappers. Snapshot cache keys include the limit, so an earlier 24-card response cannot truncate a later 96-card request. The season index and returned episode grants remain scoped and authoritative.

Qualification: real Naruto generic API pages expose 220 verified episodes across five seasons; Season 2 starts at offset 35. Synthetic tests cover unordered provider data, duplicate IDs, unknown season, specials, terminal cursor, profile authority, and one provider episode read across multiple server windows. Actual user/library data remains in private local proof artifacts.

Automatic client loading can retain the first 24 cards, then request bounded 96-card windows for the selected season using its authoritative offset and loaded count. No per-episode metadata requests are required. A captured real public Cinemeta One Piece document (1,359,991 bytes) yielded 1,242 unique episodes across thirteen cached continuation windows after the initial 24-card projection. Synthetic 1,200–1,500-episode tests cover 1/96/128 limits, invalid bounds, terminal windows, stable seasons, limit-sensitive cache keys, and configuration/profile authority.

A separate read-only qualification of the live selected-Simkl API returned 1,184 verified One Piece episodes across 23 seasons. The default initial 24 cards plus thirteen 96-card continuation windows covered the complete authoritative index without duplicates. A selected-season 128-card window returned 200 and `limit=129` returned 400. Initial detail was 498 ms, the slowest continuation 158 ms, and search plus all episode reads totaled 2.825 seconds in that isolated run; these are measured results, not a universal latency guarantee. The differing native Cinemeta and server Simkl totals reflect each provider’s verified document; clients retain the chosen metadata owner. No provider history/tracking writes were used.

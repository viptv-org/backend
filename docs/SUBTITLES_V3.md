# Scoped external subtitles

`GET /api/v3/subtitles/:kind/:id` returns canonical `SubtitleSnapshot` candidates with opaque IDs, language and labels; it never exposes an addon URL. `GET /api/v3/subtitle-content/:id` remains the authenticated normalized WebVTT path for browser clients. Existing native raw ASS/styling/legacy-byte transport remains separate.

A Ready gateway playback now advertises `delivery.external_subtitles_supported:boolean`. This is independent of embedded `subtitles_supported` and `subtitle_tracks`: both paths may exist, and one path does not imply the other. Old gateways omit `external_captions:["srt"]` in their session response, so external support is false and attachment returns 422 rather than guessing a public proxy URL.

POST `/api/v2/playback/:id/subtitles` with `{ "subtitle_id": "opaque-v3-selection-id" }`. Unknown fields and malformed IDs are rejected. The subtitle must match the **exact original playback media kind/ID**, selected profile, authenticated session family, configuration and addon revision. The host validates playback and subtitle authority before fetch, after fetch and after gateway upload. A title/episode mismatch or foreign selection is forbidden; foreign/expired playback follows existing control errors. Live and direct/native delivery do not advertise this gateway path.

Response: `{url,format:"srt",language,label,timeline_offset_seconds}`. The URL is an absolute path under the registered gateway endpoint, containing only that viewer's existing media capability. It requires **no API Authorization header or cookie** and cannot authorize gateway control. The API never forwards its bearer, addon URL or source credentials to the gateway. It fetches/normalizes the selected subtitle itself using the existing ten-second, 2 MiB, public-DNS/redirect fences; charset/BOM handling preserves supported Windows-1252/UTF-16 input. It uploads only canonical caption text. The complete attach call has a twenty-second control bound.

Caption timestamps are already rebased by the gateway's actual HLS cut position. Do not subtract `timeline_offset_seconds` again. MP4 uses the original timeline. A new seek/cut requires attachment to the new playback viewer; old URLs remain scoped to the released viewer. Discovery selections expire after ten minutes, so a later reattachment may require rediscovering candidates. An already attached caption follows the existing renewable viewer lease, not the discovery selection lifetime.

Roku `ContentNode.SubtitleTracks` uses `{Language,Description,TrackName}` with this SRT URL as TrackName. Retain existing caption-mode/system preference handling and embedded track selection. Official docs describe SRT/TTML/DFXP sidecar URLs and WebVTT through HLS/DASH manifests; a bare VTT URL is not assumed interchangeable. See [Roku content metadata](https://developer.roku.com/dev/docs/content-metadata) and [closed caption support](https://developer.roku.com/dev/docs/closed-caption). TV-web may retain authenticated VTT fetch/blob delivery; no gateway attachment is required for that working path.

Tests cover exact-media/foreign-owner denial before subtitle egress, canonical text-only gateway payloads, supported legacy charset normalization, unchanged embedded track availability, old-gateway unavailability, closed upload schema and post-release denial. Gateway tests separately cover timestamp cuts, expiry/revocation, nonrenewing reads, per-viewer isolation, memory bounds and malformed/oversized captions. No physical Roku subtitle-rendering qualification is implied by host tests.
